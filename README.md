# Quiz Project Web

Окремий frontend для [Quiz Project](https://github.com/vitaliilatysh/quizproject), який поступово замінює серверний інтерфейс на JSP, JSTL і Bootstrap. Застосунок працює безпосередньо зі Spring Boot REST API та не потребує Java-контейнера для відображення сторінок.

## Що вже працює

- адаптивний каталог тестів із пошуком і фільтром складності;
- вхід через `POST /api/v1/auth/login` і короткоживучий JWT;
- створення та відновлення власної спроби проходження тесту;
- таймер, збереження вибраних відповідей у межах вкладки й завершення спроби;
- екран результату та історія завершених тестів;
- зміна адреси API без повторної збірки;
- зрозумілі стани завантаження, помилок і відсутніх даних;
- клавіатурна навігація, видимий фокус і режим зі зменшеною анімацією.

## Технологічне рішення

Frontend використовує браузерні ES-модулі, семантичний HTML і власну CSS-систему без Bootstrap. Runtime-залежностей немає: це зменшує поверхню атак, пришвидшує завантаження та спрощує оновлення. Для збірки, тестів і локального сервера достатньо Node.js 22 або новішої версії.

## Локальний запуск

```bash
npm ci
npm run dev
```

Застосунок відкриється на `http://localhost:4173`. Spring Boot API типово працює на `http://localhost:8081`.

У Windows використовуйте ті самі команди в PowerShell або Windows Terminal.

## Підключення backend

Адресу API можна змінити на сторінці **Налаштування**. Значення зберігається лише як локальна настройка браузера. Для фіксованого production-оточення змініть `public/runtime-config.js` під час розгортання:

```js
globalThis.QUIZ_PROJECT_API_URL = "https://api.example.com";
```

Backend має дозволити origin frontend-застосунку:

```bash
CORS_ALLOWED_ORIGINS=http://localhost:4173
```

Для кількох оточень передайте список origins у форматі, який підтримує конфігурація Spring Boot проєкту.

## Безпека сесії

- логін і пароль передаються лише endpoint-у автентифікації та не зберігаються;
- JWT зберігається в `sessionStorage`, тому очищається після закриття вкладки;
- після завершення терміну дії токена користувач повертається на вхід;
- усі значення з API екрануються перед вставленням у HTML;
- повний контроль доступу залишається на backend — frontend не вважається межею безпеки.

## Перевірка

```bash
npm test
npm run build
```

Production-артефакти створюються в `dist/client`; Cloudflare/Sites entrypoint — у `dist/server/index.js`.

## Структура

```text
public/
  index.html          # оболонка SPA
  runtime-config.js   # адреса API для конкретного оточення
  styles.css          # дизайн-система й адаптивні компоненти
  js/
    api.js            # типізований контракт запитів на рівні API-клієнта
    app.js            # маршрути, екрани та взаємодії
    session.js        # JWT-сесія і локальні налаштування
    utils.js          # безпечне форматування даних
scripts/              # dev-сервер і production-збірка без залежностей
tests/                # тести API-клієнта та утиліт
```

## Відповідність старому інтерфейсу

| Старий стек | Нова реалізація |
| --- | --- |
| JSP-сторінки | клієнтські екрани та hash-маршрути |
| JSTL і server-side model | JSON із Spring Boot REST API |
| HttpSession | короткоживучий Bearer JWT |
| Bootstrap | власна адаптивна CSS-система |
| WAR як UI runtime | незалежний статичний frontend |

Старий JSP-інтерфейс можна прибирати поетапно після перевірки функціонального паритету та додавання адміністративних REST endpoint-ів.
